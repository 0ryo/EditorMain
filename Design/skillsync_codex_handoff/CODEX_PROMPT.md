# 実装依頼：Skill SyncのXR教材エディタUIをFigmaに基づいて再現

このUnityプロジェクトの教材エディタUIを、添付スナップショットから抽出した仕様に沿って実装してください。単なる見た目の提案やHTMLデモではなく、既存Unityプロジェクトで編集・表示・操作できるUIが成果物です。既存機能の再実装より、見た目の再現と既存ロジックへの適切な接続を優先します。

## 入力資料

資料のルートは `Design/skillsync_codex_handoff/` です。
対象ページはFigmaの「XR教材エディタ · UI案」、pageId=`25:2`です。
Figma URL: https://www.figma.com/design/FluJU98dJfomeAE1fOjKDD/skillsync_ui?node-id=25-2

最初に次の順序で読み、実際の画像も開いてください。
1. `README.md`、`DESIGN_SPEC.md`
2. `references/01_layout.png` から `06_export_validation.png` までの6枚
3. `references/00_foundations.png`、`07_button_states.png`、`08_field_states.png`
4. `PROJECT_CONTEXT.md`、`verification/ACCEPTANCE.md`
5. 必要な箇所について `data/screens.json`、`layout.json`、`nodes.json`、`tokens.json`、`components.json`、各画面のtree/texts、`assets/manifest.json`

`nodes.json` 全文を一度に読み込まず、`tools/query_design.py` または独自の短い読み取り処理で対象のノードだけ取り出してください。根拠ノードIDと生成するUnityオブジェクトの対応を残してください。

Figma MCPはこの資料作成時には利用上限に達していました。今回は取得済みのローカル資料を使って進め、MCP接続失敗の繰り返しで作業を停止しないでください。`references`は元パス・文字輪郭からのオフライン復元で、公式Figma書き出しとの照合は未実施です。後からクラウドを取得できても、添付版と異なる変更を勝手に混ぜないでください。バージョン差は記録してください。

## まずプロジェクトを調査

`PROJECT_CONTEXT.md` の項目を実ファイルと接続中Unity Editorから調査し、対象Scene/Prefab、Unityバージョン、UI方式、フォント、入力、3D表示、保存・手順・条件処理を把握してください。資料に存在しないプロジェクトのパス・クラス・モデルを創作しないでください。

uGUIで実装されている場合は維持し、Unity公式 `ui-ugui` を使います。UI Toolkitなら既存方式を維持し、方式を混在させません。「教材エディタ」という名前を根拠にUnityのEditorWindow/IMGUIへ変更しないでください。

既存のUnity連携が使える場合は再利用します。Unity CLI/Pipelineを使う場合は `unity-cli` Skillに従って対象プロジェクトと接続状態、利用可能コマンドを確認してから操作します。Scene/Prefabは可能な限りUnity Editor API経由で安全に保存し、GUIDやfileIDを推測してYAMLを大量生成しないでください。

## 再現の優先順位

1. 対象画面の実測レイアウト、文字、色、表示状態を合わせる。
2. 共通部品・トークン・再利用可能な階層へ整理する。
3. 既存の実データと操作を接続し、見本に明記された状態変化を再現する。
4. 基準解像度で差分確認し、修正する。その後に別解像度を確認する。

画面ノードの実効値が共通設計ボードの値と異なる場合は、今回の対象画面の再現を優先してください。18pxに揃える、余白を整える、カードに影を追加する、色を見栄えよく変更するといった独自の再設計は不要です。

## 固定する主要条件

基準は **1600×1000** です。勝手に1920×1080へ変更しないでください。各画面左上を座標原点とし、Figmaページ内の配置座標は含めません。
- ヘッダー：0,0,1600,88
- 左ペイン：0,88,264,876
- 中央ツールバー：288,112,848,47
- 3D表示：288,170,848,550
- 状態帯：288,732,848,34
- 右ペイン：1160,88,440,876
- フッター：0,964,1600,36
- 書き出し確認モーダル：490,272,620,442。暗幕はコンテンツ領域だけを覆い、ヘッダーとフッターを暗くしない。

外枠は固定寸法と伸縮アンカーを役割ごとに使い分けます。Layout Groupと子の手動位置指定を同じ軸で競合させません。別解像度は既存プロジェクト方針を優先し、未定義なら仮定と検証結果を分けて記録してください。

文字はNoto Sans JPを基準に、`text.effectiveFontSize`・ウェイト・ベースライン・実効行高を参照します。`rawFontSize`だけを採用してはいけません。画面内の21px・25pxを共通スタイルの18px・24pxへ丸めないでください。フォント不足を黙って別フォントに置き換えたり、Auto Sizeで誤差を隠したりしないでください。

## 実装する状態と接続

以下の6見本を、共通の画面構造と状態差分で再現してください。全面複製した6Canvasを作る方式は避けます。ただし、既存構造が別画面なら無理に大規模改修しないでください。
- 01：配置編集、部品A選択、配置2件。
- 02：手順2編集、部品A→目印B、中心距離50cm以内を3秒保持。
- 03：試行中、32cm、保持1.8/3.0秒。範囲外で0秒へリセット。
- 04：目印B1件＋部品A仮配置1件。クリック／ここに配置で確定、Esc／キャンセルで中止。
- 05：手順2完了、保持3.0秒、次の手順の案内。
- 06：対象未設定、修正1件のモーダル。下書きは保存されている状態。

見本を再現する固定データはテスト・プレビュー専用に隔離します。実行時の距離、時間、対象数、保存状態、ログを固定文字でごまかしてはいけません。04は01にもう1件を追加した同一データの連続状態とは限りません。`reference-fixtures.json`を参照してください。

ボタンの状態切替、入力、選択表示、仮配置の確定/取り消し、モード切替、モーダル開閉と該当箇所への誘導に必要なC#も実装対象です。既存の保存・読み込み・Undo・条件判定・3D操作があればそれへ接続し、重複実装しません。未実装の機能を押しても何も起きないボタンのまま「完成」としないでください。Figmaだけでは決まらない読み込み形式や条件種別などは無断で拡張せず、不足として記録します。

試行中の位置変更は教材の初期配置へ保存しないでください。試行終了・初期配置へ戻す操作で編集データを保護します。未完成下書きの保存と書き出しバリデーションは別に扱います。

## 3Dとアセット

Figmaの中央表示は2Dベクターです。実際のモデル・カメラ・照明は資料から復元できません。既存の3Dシーンと配置処理を接続し、UI枠の再現と3Dの見た目調整を別項目で報告してください。UI全体や3D領域を画像一枚にして完成扱いにすることは禁止です。

抽出SVGは `assets/manifest.json` で元ノードを確認して使用します。単体SVGは親の変換・不透明度や子要素を含まない点に注意してください。標準UIでよい背景はUI部品として作り、元の図形を似た汎用アイコンや絵文字へ置き換えません。SVGのインポート方法は既存パッケージに合わせます。フォント本体は別途既存アセットを確認してください。

uGUIでは装飾の不要なRaycastを外し、操作要素とモーダルの入力を正しく扱います。UIのクリックで背面3D部品が動かないこと、3D表示内の座標が正しくカメラへ渡ることを確認します。

## 成果物と完了条件

最終UIはHierarchy/Inspectorから編集可能なScene/Prefabとして保存します。実行時に画面全体を組み立てる巨大スクリプトだけを成果物にしません。構築用Editorスクリプトを使う場合は既存参照を保持し、再実行で重複しないようにします。

既存のScene、データ、Input System、レンダーパイプライン、Unityバージョン、パッケージを無断で大幅変更しないでください。ユーザーの未コミット変更を戻してはいけません。

`verification/ACCEPTANCE.md` に沿って1600×1000で6状態のキャプチャを保存し、参照と並べて確認してください。少なくとも共通レイアウト、文字、角丸、状態色、モーダル位置を確認し、差分を修正します。画像の自動差分は補助であり、フォント描画や実3Dの差を理由に完了を偽装しないでください。

最後に以下を `implementation-report.md` に記録してください。
- 変更したScene/Prefab/C#、使用したアセットと元ノードID。
- 実プロジェクトから確認できた前提、承認が必要な不足情報。
- 6状態のスクリーンショットと検証結果、残る差分。
- 実行したテスト／未実行のテストを明確に区別した一覧。
- Figmaにない実装上の判断と、既存機能への影響。

Unityを起動できない、フォントが足りない、3Dアセットがない等の理由で検証できない場合は、その部分を未検証と記録してください。「完全一致」「動作確認済み」を根拠なく報告しないでください。
