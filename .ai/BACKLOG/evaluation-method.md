# 評価方法と評価軸

2026-10-20作成。研究の評価設計の要点をまとめる。詳細な判断と根拠は `~/research/authoring-tool-evaluation/evaluation-design.md`（論文草稿は `report.md`）。評価の実施計画は [research-integration-plan.md](research-integration-plan.md) のEVA項目で扱う。

## 1. 主張と証拠の対応

主張は4つに分け、それぞれ別の証拠で支える。教員の人数に依存するのは「できるか」だけにする。

| 主張 | 証拠 | 参加者 |
|---|---|---|
| できるか（専門知識がない教員が、少ない説明で作成・修正を完走できるか） | 教員5名の使用評価（E2） | 教員5名 |
| 何が作れるか（機能性・表現力） | 実在する実習手順の再現率（E1） | 不要 |
| どれだけ速く安く済むか | 従来方式（開発者による実装）との比較（E3） | 不要（事例比較） |
| 品質はプロ製と遜色ないか | 作成者を伏せた盲検評定（E4） | 評価者（教員・学生など） |

## 2. 評価軸

| 軸 | 測るもの | 方法・記録 |
|---|---|---|
| 達成度 | 要件どおりに配置・順序・条件を設定できたか | 参照解のチェックリストとの一致率、完走の有無 |
| 教育意図の反映 | 教員の成功基準・注意点が教材に表れたか | 作成前に教員が成功基準と注意点を書き、作成後に本人と第三者が照合 |
| 操作性 | 迷い、誤操作、支援要求 | 思考発話と録画から回数と場面を記録。SUSは記述統計のみ（基準値68は参考） |
| 作成・修正時間 | 作業時間と、依頼方式の往復を含む時間 | 課題ごとに記録。修正時間を重視。素材準備時間は別に記録 |
| 品質（手順・条件・指示文） | 手順の正しさ、条件の妥当性、指示文のわかりやすさ | 盲検評定。LORIを手本に5段階評価。参照解との構造的一致も機械的に数える |
| 表現力 | 実習手順のうち表せた割合、表せない手順（分岐・失敗時処理など） | 実習テキスト3領域以上から手順を集め、6種の条件で判定 |

「初見の教員が説明少なく迷わず完走できるUI」が最重要の品質目標。

## 3. 評価の流れ

1. **予備評価（学生・1〜2回）**: 教員の前に、学生に指示書と説明だけでUIを理解し教材を作れるか確かめる。詰まった箇所はUIや説明を直す。教員の回は総括的評価に回す。
2. **教員評価（E2・5名）**: 新規作成（T1）と修正（T2・変更依頼3件程度）。参加者ごとに結果を出し、平均だけにしない。事後インタビューで意図の反映、授業での利用意向、不足点を聞く。
3. **従来方式との比較（E3）**: 同じ教材を開発者が従来方式で作り、作業時間・コード行数・ファイル数を記録する。差が桁で出る比較を選ぶ。
4. **盲検評定（E4）**: 教員製と開発者製の教材を、作成者を伏せて評価者が評定する。
   - 学生による評定（手順・条件設定・指示文のわかりやすさを5段階）は、教材が作れたことの証明に用いる。
   - 他の教員・技術職員・XR開発者による評定は、品質の比較に用いる。
5. **学習者側の評価（E5・XR実行アプリ接続後）**: 教員製と開発者製で学生を訓練し、完了率や実機作業を比べる。

## 4. 指示書の扱い

- 教員には、作りたい教材の要件だけを記した指示書を渡し、説明してから使ってもらう。参照解は教員に渡さず、採点にだけ使う。
- UIの操作手順は指示書に書かない。UIを理解できるかも評価対象に含める。

## 5. 人数と限界

- 5名で言えるのは「この5名はできた」まで。完了率の95%信頼区間は51〜100%ほど（adjusted-Wald）。
- 主張の型は統計による一般化ではなく、存在証明と大きな差の事例比較とする。n=5でp値は主張しない。
- 人数の制約は、母集団に対する割合、時間・協力の制約、先行研究の人数（Cassola 2名、Augmented Math 5名、FlowTrainer 8名、Horst 17名、Vargas González 2019 28名）とあわせて書く。
- 限界: 1校・2系（機械・電気）に限られる、開発者比較は事例である、XR側の判定が未検証、押す・引く・もつ・回すはPC上で試行できない。

## 6. 未確定事項

- 盲検評定で比較する作成者の組み合わせ、評価項目の数、集計方法は予備評価の後に決める。
- 数値の合格基準は予備評価の後、本評価の前に決める。
- 対象の授業・教員、協力人数と日程。
