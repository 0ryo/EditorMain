# タイヤ交換教材を中心とした今後の実装計画

2026-09-10更新。タイヤ交換教材の操作表現と評価に関する残作業を扱う。直近の表示改善は別計画へ分離する。

## 1. 研究の対象と到達点

当面の対象を「学校・実習で使う、タイヤ交換の部品・操作・手順を予習／復習する教材の制作」に絞る。用意済みの3Dモデルを使い、教員が授業に合わせて手順や説明を作成・修正できることを中心価値とする。単発授業や短期間の利用、既存教材の一部分の変更も想定する。

外部委託費が高いことは現時点では発表者側の認識であり、一般的な事実や費用削減の証拠として断定しない。対象教員の実際の制作・調達方法、予算、修正頻度、準備時間を聞き取り、必要なら具体的な見積事例を集める。「簡単に作れる」だけでは教材の有用性を証明できないため、制作負担と教育内容の妥当性を別々に評価する。

3Dモデリング自体は対象外。既存アセットやChatGPT等を利用して用意したモデルを入力として扱う。ただし、AI生成かどうかにかかわらず、必要部品・寸法・構造が教材用途に適合するかは確認する。素材の準備・修正にかかった時間は、教材編集時間と分けて記録し、総作業負担から除外しない。

最小到達点は「車1台の交換対象1輪と必要なナット・工具を対象に、部品を指定した把持・回転・着脱の手順を作成し、保存・再読込・出力後にも同じ対象を参照して実行できる」こと。実車整備全般、力覚、実トルクの再現まで達成したとは主張しない。

## 2. コメントと対応

| コメント | 計画への反映 |
|---|---|
| 教員に制作時間があるか、作った教材は役立つか | 対象授業を限定。テンプレート再利用、修正のしやすさ、制作時間と内容妥当性を評価 |
| オブジェクトは用意されている前提 | 素材制作は対象外とし、入力モデルの部品構造と品質の要件を明文化 |
| 近づける以外の手順が必要 | 既存の把持等を活用し、軸を指定した回転、取り外し、取り付けを追加 |

## 3. 既存機能との切り分け

| 項目 | 現行ソースで確認した状態 | 今後必要なこと |
|---|---|---|
| 成功条件 | `ConditionTypeCatalog`に近づける、近づけて保持、離す、向きをそろえる、つかむ、つかんで手放すが存在 | 重複追加せず、部品参照と実行側入力を接続して検証 |
| 条件判定 | `ScenarioPlaybackSession.cs`に位置・回転・把持状態を受け取る共通判定あり | VR側アダプターと実機確認。項目の存在だけでVR対応済みとはしない |
| 回転 | `RotationMatch`は2対象の現在の向きの差を判定 | 回転軸・方向・累積角度を扱う別の条件が必要 |
| プレビュー | 成功を模擬してグラフ進行を確認 | 実操作による条件判定と区別して評価 |

既存方針「成功条件がそろうまで待機」「失敗分岐を増やさない」を維持する。

## 4. 実装フェーズと完了条件

優先度は本テーマ内の順番。既存UIの操作不能が残る場合は先に解消する。期限・実行アプリの改修範囲が未確定のため、日数の確約はせず各段階の完了条件で進める。

### P1 / C — 回す・外す・取り付ける

条件の追加だけでなく、「動かせる仕組み」と「成功したかの判定」を対応させる。

| 操作 | 設定・実装内容 | 成功判定の例 |
|---|---|---|
| つかむ／手放す | 既存条件を部品IDへ対応。実行側の把持状態を接続 | 指定部品の把持／当該手順内の把持後の解放 |
| 回す | 操作支点、基準部品、local軸、正負方向、必要角度／回転数 | 指定軸回りの符号付き累積角度が目標へ到達 |
| 外す | 取り付け状態、解除可能な前提、抜く軸・距離 | 解除後に指定部品が取り付け先から所定距離移動 |
| 取り付ける | 対応する取り付け先と部品上の接続点、位置・角度の許容差、スナップ | 正しい取り付け先へ位置・向きがそろい接続された |

- ナット回転は工具と対象ナットが接続されている間だけ計測する。工具だけを空中で回して成功しないようにする。
- 回転はフレーム間の角度を軸方向に累積し、360度越え、逆回転、手の持ち替え、親である車の回転を扱う。初期案では逆回転は進捗から差し引き、握り直しで累積値を消さない。リセットは手順開始／教材リセットの時点で行う。
- 実装時は1フレームに180度以上回る曖昧性も考慮し、実行側が累積角度を供給する案と、姿勢差から積算する案を入力仕様に合わせて選ぶ。
- 近接・向き判定だけでは接続状態にならない。取り付け先への固定／解除と、装着状態の管理を追加する。
- 現行の成功条件は達成を記憶するため、近接と向きを別条件に置くだけでは同時成立を保証しない。装着判定は位置・向き・接続先を同時に確認する専用評価とする。
- 工具のプリセットから軸・支点の初期値を設定し、画面で確認・修正できるようにする。
- 共通判定はServices、入力・拘束・スナップは実行側アダプターに置く。新規XR依存が必要な場合は必要性と代案を示してから扱う。

完了条件：正しい対象・方向・操作で達成でき、別ナット、逆回転、車全体の回転、工具の空回し、誤った取り付け先で誤達成しない。成功しなければ現手順で待機する。

### P1 / D — タイヤ交換教材と評価

- 最初は作業準備が完了した車の1輪を使い、工具把持→ナットの回転→ナットの取り外し→タイヤの取り外し→交換タイヤの取り付け→ナットの取り付け・回転、という操作表現を確認する。
- 上記は実装検証用の部分シナリオである。実際の教材の作業順序、安全措置、締付条件、説明内容は対象教員／専門家と確定し、評価前に確認する。
- ナット数や対象を変えて再利用できる手順テンプレートを作る。まず既存の複製機能で試し、反復記述が負担になる範囲を機能化する。
- 対象部品の強調、回す方向、現在の進捗、次に行う操作を表示する。見た目の品質と操作・説明の分かりやすさを両方改善する。
- 編集→保存→再読込→素材同梱出力→実行アプリの読込→実操作の一連の確認を行う。

完了条件：専門家が確認した部分教材を第三者が作成・修正でき、実行側で最初から最後まで試せる。

## 5. 評価で確かめること

| 観点 | 方法・記録 |
|---|---|
| 教員の時間を節約できるか | 同じ素材・同程度の内容で新規制作と一部修正の時間、完了率、支援回数を測る。比較先は対象教員の現行手段を聞いて決める |
| 部品設定の負担 | 自動抽出数、必要な修正数、部品設定にかかった時間、誤選択を記録 |
| 教材として妥当か | 専門家による手順・対象・説明・判定のレビューと、重大な不足の解消を確認 |
| 学習者に伝わるか | 操作完了率、順序や部品理解の確認、迷った箇所を記録。学習効果を主張する場合は事前／事後や比較条件を設ける |
| 外観と操作品質 | 部品の視認性、寸法・軸・支点、操作応答、誤判定を確認 |

数値の合格基準と比較条件は予備試行後、本評価の前に決める。制作のしやすさだけから学習効果を結論付けない。

## 6. 後回しにする範囲

- 任意の結合メッシュからエンジン等を意味的に認識する自動分割。
- エンジン・ウォッシャー液・ダッシュボード／ボンネット等への教材拡張。階層基盤は共用し、開閉軸や角度制限はタイヤ交換の完了後に追加する。
- 全輪、車種ごとの差、ジャッキ等を含む完全な整備工程、実トルク／力覚の再現。
- PlayerへのFBX直接取込、モデル自動生成機能、汎用物理シミュレーター。
