# Unityアプリ＝なにもの？
- **ゲームエンジン**：3D/2D描画・物理・音・入力などをまとめて面倒見てくれる土台。  
- **Scene（シーン）**：ステージや画面の単位。  
- **GameObject（ゲームオブジェクト）**：シーンに置く物の箱。  
- **Component（コンポーネント）**：箱に付ける機能（例：見た目＝MeshRenderer、当たり判定＝Collider、動き＝自作C#スクリプト）。  
- **Prefab（プレハブ）**：よく使うオブジェクトの設計図。好きな場所に何個でも置ける。  
- **Script（C#）**：振る舞いを書くコード。  
→イメージ：レゴ(=Prefab)を場に置く(=GameObject)、ブロックごとに性質(=Component)を付けて、設計図(=Prefab)は後から何度でも再利用。

# つくりたいアプリは可能？（要点）
- **可能です。**必要な要素は：
  1) **ランタイム・レベルエディタ**（ゲーム中にオブジェクトを置くUIと操作）  
  2) **セーブ/ロード**（配置結果をデータに保存→後で復元）  
  3) **プレイモード**（保存データからコース生成して遊ぶ）  
  4) **Meta Quest対応**（VR操作＆Android向けビルド設定）
- **「Meta Questで読み込める形式」についての注意**：  
  OSが勝手に「コース形式」を理解してくれるわけではありません。**あなたのQuest用アプリが自分で読み込む独自フォーマット（例：JSON）**を定義し、そのファイルをアプリ内で開いてステージを組み立てる形になります。  

# 初心者向けロードマップ（最短MVP）
**フェーズA：PC（マウス）でMVP**
1) Unity Hub＋LTS版Unityを入れる（テンプレは「3D（URP）」が軽くて◎）。  
2) **Prefab群**を作る（床ブロック、壁、敵のダミー等）。  
3) **配置UI**：画面上のボタンで選んだPrefabをマウス位置/グリッドにスポーン、移動・回転。  
4) **保存**：置いたオブジェクトの**種類**と**位置/回転/スケール**を**JSON**に書き出し。  
5) **読み込み**：JSONを読み、対応するPrefabをInstantiateして復元。  
   - 初心者は**JSON方式**が一番簡単＆安全（外部アセットを持ち込まない）。  
   - 参考データ形（例）：
     ```json
     {
       "version": 1,
       "objects": [
         {"type": "Floor", "pos":[0,0,0], "rot":[0,0,0], "scl":[1,1,1]},
         {"type": "Wall",  "pos":[3,0,0], "rot":[0,90,0], "scl":[1,2,1]}
       ]
     }
     ```
   - 「type」→アプリ内に用意したPrefab名と対応付け（Dictionaryで紐付け）。

**フェーズB：VR対応（Questでも編集 or 再生）**
1) パッケージ：**OpenXR + XR Interaction Toolkit + 新Input System**（公式パッケージ）。  
2) **操作**：レーザー（Ray Interactor）で掴む/移動/回転、スナップ（等間隔移動）を用意。  
3) **ビルド**：Android/ARM64、URP、ASTCテクスチャ、OpenXR有効でQuestへ。  
4) **保存場所**：`Application.persistentDataPath` にJSON保存。外部から取り込みたい時はファイルピッカーやWebダウンロードを用意。

**フェーズC：共有（任意）**
- **一番簡単**：サーバにJSONを置いてHTTPでダウンロード→読み込み。  
- 端末内共有ならExport/Importを実装（共有シートや特定フォルダ）。  
- 将来はユーザー投稿/レーティングなども実装可（Firebase/PlayFab等）。

# ちょい実装ヒント（超最小サンプルの考え方）
- **PrefabRegistry**（Inspectorで`type`→`Prefab`を紐付けたScriptableObject）を作る。  
- **Save**：シーン内の配置対象に「LevelItem」スクリプトを付け、`type`と`Transform`を列挙→`JsonUtility`や`Newtonsoft.Json`で保存。  
- **Load**：JSONを読み、`type`→Prefabを参照して`Instantiate`、`pos/rot/scl`を適用。

> 用語補足：  
> **ScriptableObject**＝設定表みたいなアセット。コードを書かずにインスペクタで編集できるデータ容れ物。  
> **Instantiate**＝Prefabから実体を生成。  
> **Transform**＝位置・回転・大きさ。  

# パフォーマンス＆VRならではのコツ（Questで快適に）
- **URP**を使って軽量レンダリング。  
- **動的ライト/影を最小限**、可能なら**ベイク**（あらかじめ光計算してテクスチャ化）。  
- **Draw Call削減**：メッシュ結合、マテリアルの共通化、テクスチャアトラス。  
- **LOD/オクルージョン**：遠景は粗く、見えないときは描かない。  
- **物理は控えめ**：Rigidbodyを必要な物だけに。  
- **GC対策**：毎フレームnewしない、オブジェクトプール。  

# 「パッケージ化」って？
- **JSONだけでOK**：Prefabはアプリに同梱、コースは配置データだけ（軽い・安全）。  
- **AssetBundle/Addressables**（上級）：外部アセットを後から配る仕組み。プラットフォーム別ビルドや配信管理が必要で少し難度UP。初心者MVPは**JSON方式を推奨**。

# よく出る用語ミニ辞典
- **Collider**：当たり判定。  
- **Rigidbody**：物理（重力・衝突）を有効化。  
- **NavMesh**：AI移動用の歩行可能面。  
- **URP**：軽量＆モバイル向けレンダーパイプライン。  
- **OpenXR**：VRの共通規格。Quest対応にも使う。  
- **XR Interaction Toolkit**：VRの掴む・指す等の標準コンポーネントセット。

# 実現可能性まとめ
- **技術的には◎**：ランタイム配置、保存/読込、VRプレイは王道パターン。  
- **現実的な難所**：  
  - 直感的な編集UI作り（スナップ、回転、削除、Undo/Redo）  
  - VR操作のUX調整（酔い対策、移動方法、UI視認性）  
  - パフォーマンス最適化（QuestはモバイルGPU）  
- **IP注意**：任天堂のマリオ素材や名前は使わず、**完全オリジナル**で。

2) キューブPrefabを「床」「壁」など数種作る。

## 5. データ設計（JSONフォーマット／インターフェイス契約）
### 5.1 方針
- **軽量・可読**な**JSON**で表現。  
- **Prefabレジストリ方式**：`type`（文字列ID）→Quest側/Editor側の**対応Prefab**を**同名ID**で紐付け。  
- **後方互換**：`version`でスキーマを明示、将来の追加項目は**非破壊**で拡張。

### 5.2 座標と単位
- 座標：**Unity準拠（Y-Up, Z-Forward, X-Right）**  
- 単位：**メートル**  
- 原点：**床中央**（エディタ起動時の基準）

### 5.3 最小スキーマ（MVP案）
```json
{
  "version": 1,
  "meta": {
    "title": "タイヤ交換・基礎コース",
    "description": "車両と交換用タイヤを使った基礎作業の配置",
    "author": "Teacher A",
    "createdAt": "2025-09-02T12:00:00Z",
    "targets": ["Quest3", "Quest2"],
    "grid": { "size_m": 0.1, "rot_snap_deg": 15 }
  },
  "requiredActions": [
    {"id": "fix_vehicle", "name": "車体固定"},
    {"id": "remove_tire", "name": "タイヤ取り外し"},
    {"id": "attach_tire", "name": "交換タイヤ装着"}
  ],
  "objects": [
    {
      "id": "obj-001",
      "type": "Env/Floor",
      "pos": [0.0, 0.0, 0.0],
      "rot": [0, 0, 0],
      "scl": [10, 1, 10],
      "static": true
    },
    {
      "id": "obj-100",
      "type": "Vehicle/Car_Generic",
      "pos": [0.0, 0.0, 2.0],
      "rot": [0, 180, 0],
      "scl": [1, 1, 1],
      "params": { "wheel_focus": "front_right" }
    },
    {
      "id": "obj-200",
      "type": "Toolbox/Basic",
      "pos": [-1.5, 0.0, 1.2],
      "rot": [0, 30, 0],
      "scl": [1, 1, 1]
    },
    {
      "id": "obj-300",
      "type": "Tire/Replacement",
      "pos": [1.0, 0.0, 1.0],
      "rot": [0, 0, 0],
      "scl": [1, 1, 1],
      "params": { "rim_size_inch": 16 }
    }
  ]
}
```
- `type`：**カテゴリ/名称**の**文字列ID**（例：`Vehicle/Car_Generic`）。  
- `params`：後から拡張しやすい**任意プロパティ**格納領域。  
- `requiredActions`：**名称とIDのみ**（Quest側で手順をマッピングし、達成判定）。  
- 将来拡張例：`zones`（作業禁止/必須エリア）、`markers`（注記）、`workflow`（DAG的な手順依存）、`lighting`（環境設定）等。

## 6. オブジェクトIDとPrefabレジストリ
- エディタ側に**Prefabレジストリ**（ScriptableObject）を持ち、`type`→Prefab参照をGUIで管理。  
- コースJSONには**`type`のみ**を書き出す（見た目・コリジョン・当たり判定はQuest側Prefabが定義）。  
- この方式により、**見た目の差替えや最適化をQuest側で独立実施**できる（モバイル最適化／LOD等）。

- **スナップ**：移動（0.1m）、回転（15°）のオンオフ切替。  
- **アウトライナー**：名前変更、親子付け（将来）、可視/ロック切替。  
- **インスペクタ**：Transform数値、`params`（簡単な数値・テキスト）編集。  
- **Validation**：エラー/警告をステータスバー表示、エクスポート時にもチェック。

```csharp
public class CommandStack {

  Stack<IEditorCommand> redo = new();
  public void Execute(IEditorCommand cmd) { cmd.Do(); undo.Push(cmd); redo.Clear(); }
```

# 概要
本研究は、教員が短時間で訓練コースを設計し、学習者がMeta Quest上で安全に反復学習できるVR実習環境を構築するものである。システムは（1）コース作成ツール、（2）VR実行アプリ、（3）カリキュラム（学習目標・手順・3D資産）、（4）成績管理Webアプリの四要素で構成し、コースは拡張可能なJSONで受け渡す。初等タスク（例：タイヤ交換）を題材に、編集→配布→実行→評価までのワークフローを定義し、MVPから段階的に実装と検証を進める。

## 緒言
実機不足や安全面の制約により、技能訓練の反復は難しい課題である。近年、HMD型VRは技能・知識の向上に有効であることが報告されており、教育課程への導入余地が大きい。本研究は、教員主導でシナリオを設計し運用可能なVR実習基盤を提示することを目的とする。

## 研究方法
四要素を疎結合に設計する。（1）PC向けスタンドアロンのコース作成ツールは、グリッドスナップ配置、プレハブカタログ、手順・成功条件メタデータ編集、簡易妥当性チェックを備える。（2）VR実行アプリはOpenXR準拠でMeta Quest 2/3に対応し、JSONを読み込み、必須手順の達成を確認するゲーティングで進行を制御する。（3）カリキュラムは学習目標・評価観点・3D資産をひとまとまりとして管理する。（4）成績管理Webアプリは進捗・履歴・エクスポートを提供する。評価はMVP段階では機能妥当性（動作・安定性）と作成時間を中心に行い、その後、学習効果測定へ拡張する。

## 結果
MVP-1として、オブジェクトの配置・選択・移動・回転・削除・複製およびUndo/Redoを実装対象とし、Prefabレジストリとスナップ機構を含むプロトタイプ設計を確立した。JSONインターフェイス（version付き、`type`と`params`による拡張）を定義し、編集結果をVR側で再現可能とする見通しを得た。

## 考察
編集ツールと実行アプリをJSONで分離する設計により、教員は教材設計に、VR側は最適化にそれぞれ専念できる。ゲーティングは学習順序と安全性の確保に有効であり、教材の再利用・派生にも適する。一方で、手順定義の粒度と作成負担、モバイルGPUにおける描画負荷が課題であり、テンプレート化とプロキシ資産の併用で軽減可能である。

## 結言
本研究は、コース設計・実行・評価をつなぐVR実習基盤を提案し、MVP段階の設計と実装計画を示した。今後は初期科目での授業内試行により、作成時間・学習成果・運用性を定量評価し、Web連携や共同学習機能へ拡張する。

# 教育現場におけるXR技能実習教材の構築と開発効率化ツールの設計  

伊藤 瞭汰¹  
¹ 一関工業高等専門学校 専攻科  

---

### 概要  
本研究は、実機訓練の安全性・コスト・反復性に課題を抱える技能教育分野において、XRデバイスを活用した実習教材の構築を目的とする。システムは「コース作成ツール」「VR実行アプリ」「カリキュラム（3D資産と学習手順）」「成績管理Webアプリ」で構成され、教員が短時間でコースを設計し、学習者がMeta Quest上で反復練習できる環境を整備する。特に本稿では、開発コストを低減させるための編集支援ツール設計について報告する。

---

### 1. 背景  
製造・整備・医療などの技能教育では、設備コストや安全性の制約により、十分な反復訓練が困難である。近年、XR（Extended Reality）技術を利用した仮想実習教材が注目されており、現実作業の模擬体験を通じた理解促進が期待されている。一方で、教材開発には3Dモデルや手順設計の知識が必要であり、教育者単独で開発を進めることが難しいという問題がある。

---

### 2. 目的  
本研究は、教員が専門知識を持たずとも実習教材を効率的に設計・運用できる仕組みを構築し、技能学習の再現性と導入コストの低減を図ることを目的とする。特に、教材制作の自動化・省力化を支援する「コース作成ツール」の開発に焦点を当てる。

---

### 3. 研究方法  
システム全体は四要素から構成される。  
(1) **コース作成ツール**：PC向けスタンドアロンアプリとしてUnityで実装し、グリッドスナップによる直感的な3Dオブジェクト配置、手順・成功条件の設定、簡易バリデーションを備える。出力データは拡張可能なJSON形式とし、VR実行側と統一仕様で連携する。  
(2) **VR実行アプリ**：Meta Quest 2/3上で動作し、JSONを読み込んでコース内容を再構築、必須手順を満たした場合のみ次に進めるゲーティング機能を実装する。  
(3) **カリキュラム**：学習目標と評価基準を含むシナリオ群として設計し、初期題材にタイヤ交換を採用した。  
(4) **Webアプリ**：学習履歴・成績の管理とコース配布を行う。

---

### 4. 結果  
MVP（Minimum Viable Product）段階として、オブジェクト配置・移動・回転・削除・複製およびUndo/Redo機能を持つ編集ツールの試作を完了した。プレハブ管理とスナップ制御によって配置作業を効率化し、JSONデータとしてVR実行アプリで正確に再現可能であることを確認した。

---

### 5. 考察  
本システムにより、教材開発の初期段階で必要だった3Dエディタ操作やUnity知識の多くを省略でき、教員が自ら教材を設計できる見通しが得られた。また、JSON形式を介したデータ統一は、教材の再利用性と拡張性を高めることが示唆された。一方で、手順定義の粒度調整やVR機器の性能差による負荷変動が今後の課題として残る。

---

### 6. まとめ・今後の展望  
本研究では、教育現場での技能実習を支援するXR教材システムを提案し、その中核となるコース作成ツールを設計・試作した。今後は他分野の技能訓練への応用、UI改善、共同編集・クラウド連携機能の追加を行い、学習効果と教育コスト削減の両立を目指す。

# 教育現場におけるXR技能実習教材の構築とコース作成支援ツールの設計

伊藤 瞭汰¹  
¹ 一関工業高等専門学校 専攻科

---

### 概要  
本研究は、技能教育における安全性・再現性・反復性の課題に対し、XR（Extended Reality）を用いた実習教材を構築し、教員が短時間で訓練コースを設計・配布し、学習者がVR（Meta Quest）上で反復練習できる環境を整えることを目的とする。システムは（1）コース作成ツール、（2）VR実行アプリ、（3）カリキュラム（学習目標・手順・3D資産）、（4）成績管理Webアプリの四要素で構成し、コースは拡張可能なJSONで受け渡す。本稿では、全体像に加えて、開発コストを低減させる要の要素であるコース作成ツールの設計と到達点を中心に報告する。

---

### 1. 諸言  
製造・整備・医療等の技能教育では、設備コストや安全配慮、時間割制約により十分な反復訓練が難しい。近年、XRは実務作業の可視化・遠隔支援・標準作業の遵守に資する技術として産業分野での適用が進みつつある一方、導入には運用設計や教材開発の負荷、3D資産調達や手順定義の難易度といった課題が残る[1]。教育現場においては、教員自身が学習目標に合わせて迅速に教材を設計・更新できる仕組みが求められる。

---

### 2. 目的  
本研究の目的は、教員が専門的な3D/ゲーム開発知識を必ずしも要さずに、学習目標に即した実習教材を効率的に設計・運用できるワークフローを構築することである。全体システムの枠組みを示すとともに、**共同研究の中で筆者が担当する要素がコース作成ツールであるため、本発表では当該ツールの設計思想と実装到達点を相対的に詳述**する。

---

### 3. 研究方法  
システムは疎結合な四要素で設計する。（1）**コース作成ツール**はPC向けスタンドアロンのUnityアプリとして実装し、グリッドスナップによる直感的な3Dオブジェクト配置、カタログ（Prefabレジストリ）による部品選択、学習手順と成功条件のメタデータ付与、基礎的な妥当性チェックを備える。出力は拡張性を重視したJSONで、`version`管理と`type/params`によってVR側とデータ契約を結ぶ。（2）**VR実行アプリ**はMeta Quest 2/3上でJSONを読み込み、必須手順の達成を検証するゲーティングにより学習の順序性と安全性を担保する。（3）**カリキュラム**は学習目標・評価観点・手順記述・参照3D資産で構成し、初期題材としてタイヤ交換を設定して教材設計プロセスを検証する。（4）**成績管理Webアプリ**は進捗・履歴・成績の可視化とコース配布を担い、運用面の一元管理を可能にする。

---

### 4. 結果（筆者担当：コース作成ツールの現到達点）  
現段階では、編集ツールの基礎操作群を実装し、実用上の手応えを得ている。具体的には、（a）ビューポートのオービット／パン／ズームと床グリッド表示、（b）Prefabレジストリに基づくカタログUIからの配置、（c）床へのレイキャストと**0.1 m**位置スナップ・**15°**回転スナップ、（d）選択・ハイライト、（e）移動・回転・削除・複製、（f）**Undo/Redo（配置・削除・移動・回転に対応）**の動作を確認した。操作衝突を避けるため、UI上のポインタ検知による入力ブロックを施し、回転中心の不整合はPrefabのPivot統一で抑制した。内部実装では、配置・編集操作をコマンドとして記録するスタック方式を採用し、ドラッグ終了時に1操作として集約して巻き戻しの再現性を高めた。これらにより、カリキュラム作成に必要な基本配置作業を低学習コストで反復できる見通しを得た。なお、JSON入出力および高度な検証機能は次段階で実装予定である。

---

### 5. 考察  
編集作業をスタンドアロンツールに切り出し、VR実行とはJSONで連携する構成により、教材設計と実行最適化を分業可能とした。これは、教育現場側の更新頻度や題材差し替えに対応しつつ、VR側では描画最適化・物理挙動の改良を独立して進められる利点がある。基礎操作の確立は、教員による教材内製のハードルを下げ、試行錯誤サイクルの短縮に寄与する。一方、課題として、手順定義の粒度（どこまでを「必須」とするか）、3D資産の写実性とパフォーマンスのトレードオフ、複数教員・複数学科での運用ルール整備が挙げられる。これらには、テンプレート化（雛形コース／チェックリスト）、プロキシ資産と高精細資産の二層管理、バージョンド管理とガイドライン策定が有効と考える。

---

Abstract: Simulation has evolved from basic practice to Immersive Extended Reality (I-XR).
This systematic review examined 56 published studies on the impact of I-XR, including
virtual reality (VR), augmented reality (AR), and mixed reality (MR), on the education of
medical and nursing students, specifically their skill competency, and knowledge acqui-
sition. The results demonstrate the significant potential of I-XR in healthcare education,
with 42.5% of VR studies, 42.9% of AR studies, and the single MR study also demon-
strating greater improvements in clinical skills and knowledge acquisition compared to
non-immersive (non-I-XR) training conditions. In contrast, only 2.5% of VR studies and
7.14% of AR studies favored non-I-XR methods. It is important, however, to acknowledge
the 26.8% of studies that showed mixed results (some evidence for the I-XR methods on
some outcomes, but also some evidence for the non-I-XR methods, on other outcomes).
Notably, the review also identified a critical gap in the theoretical foundations of I-XR
learning, highlighting the urgent need for research to inform the effective pedagogical im-
plementation of these powerful tools. We offer a preliminary framework to address the lack
of learning theory in healthcare I-XR training, with implications for pedagogical practices.

Keywords: medical/healthcare education; conventional simulation-based learning; Immersive
Extended Reality (I-XR); learning theory

Simulation-based training is a pedagogical approach that employs simulated scenarios

or environments to improve clinical skills, mainly among health field workers. The objective
is to replicate real-world situations to provide a realistic and immersive experience without

complements conventional teaching methods by focusing on improving skill acquisition,
decision-making, and teamwork (Ajemba et al., 2024). Such clinical experiences can help
create opportunities for students to apply didactic content to clinical practice, which allows
them to bridge knowledge, skills, and competency (Hultquist & Bradshaw, 2016).

Halsted’s “see one, do one, teach one” model, while groundbreaking in 1890, is now
criticized for prioritizing rapid experience over deliberate skill development and patient
safety (Ayub, 2022; Baskaran et al., 2023). This approach raises concerns about inadequate
preparation, potentially leading to medical errors and a lack of emphasis on critical thinking

Simulation-based medical education (SBME) (Saleem & Khan, 2023) offers a viable

in a safe learning environment. It incorporates a wide array of techniques, ranging from
basic mannequin-based simulations and standardized actor-patients to complex multimedia
scenarios (Shah et al., 2022; Ziv et al., 2003). Through SBME, students can build confidence
and competence and ultimately enhance patient safety and the overall quality of care.

According to Baskaran et al. (2023), SBME has three primary objectives: (1) the
execution of clinical skills, (2) the supervised practice of that skill, and ultimately, (3) the
independent and confident performance of clinical skills. This educational approach
extends beyond technical proficiency to encompass the development of exteroceptive
awareness among aspiring professionals. Exteroceptive awareness, or the ability to perceive
and interpret external stimuli, is crucial for stress management, confidence building, and
overall well-being (Baskaran et al., 2023). Specifically, cultivating exteroceptive awareness
helps regulate the sympathetic nervous system and manage stress responses in high-
pressure situations, such as surgical procedures, thereby enabling healthcare professionals
to maintain their composure and perform optimally.

Specifically, significant positive effects of SBME (vs. non-simulated methods) have
been shown for theory knowledge, analytic skills, learning interest and understanding,
satisfaction, cooperative ability, problem-solving ability, teaching success, and situation
awareness (Su & Zeng, 2023). Additionally, SBME is effective in assessing teamwork and
communication among healthcare providers (Dodson et al., 2023; Sezgin & Bektas, 2023).
These benefits translate into improved patient outcomes and reduced healthcare costs
(Le Cook et al., 2013; Issenberg et al., 2005), establishing it as a fundamental pillar of health-
care clinical training (Saleem & Khan, 2023) that provides a safe and effective environment
for learners to develop crucial skills and decision-making abilities (Pottle, 2019).

1.1. Integration of I-XR in Healthcare Education

Recent technological advancements have further propelled SBME to include methods
like virtual reality (VR), augmented reality (AR), and mixed reality (MR) (Tang et al., 2020).
These methods are thought to better equip healthcare students with practical experience
and readiness for actual scenarios and procedures (Horowitz et al., 2022; Wu & Norvell,
2022). Such technologies are increasingly seen as having promise for teaching healthcare
professions, even though the largest market is still in the entertainment and gaming industry
(Bankar et al., 2023; Wohlgenannt et al., 2020).

Extended reality (XR) is an umbrella term used to include VR, AR, and MR (Aebersold
& Dunbar, 2021), but typically refers to computer-generated images in the wearer’s field of
vision and includes the range of the user’s view of the world that can exist from fully visible
to fully occluded (Zhang et al., 2023), thus blurring the line between the digital world and
the physical world (Chengoden et al., 2023). Finally, Immersive Extended Reality (I-XR)
is characterized as a screen-based simulation that highlights the 3D nature of patients,
graphics, sound, and navigation through the environment (McGrath et al., 2018). The use
of I-XR for healthcare education is becoming increasingly recognized as it allows an almost
unlimited number of clinical scenarios to be simulated, with the ability to allow real-time
feedback on student progress and patient status (Lu & Bowman, 2021), and can improve
users’ motivation, engagement, and enjoyment in educational learning across different
domains by providing powerful experiential learning (Fokides et al., 2021; Tonteri et al.,
2023). As more healthcare educators pioneer innovative methods, I-XR is emerging at the

forefront of teaching and learning and is preparing healthcare students with practical skills,
hands-on experience, and preparedness for real-world scenarios and procedures (Horowitz
et al., 2022). Embracing these changes represents an innovative step toward cultivating a
more knowledgeable, proficient, and self-assured healthcare workforce, benefiting patients
and enhancing healthcare education.

1.2. Review of I-XR Studies for Training Effectiveness in Healthcare Education

Whether I-XR methodologies specifically improve student learning outcomes com-
pared to non-immersive (non-I-XR) methods remains a subject of debate. Historically,
the majority of meta-analytic studies have focused on medical students’ surgical skills
(Zhang et al., 2023). Within the last five years, there has been a surge of systematic reviews
and statistical meta-analyses seeking to explore whether I-XR (specifically VR, AR, and
MR) methodologies improve students’ learning outcomes across domain-specific skills,
procedural outcomes, and even non-technical skills (e.g., empathy, self-efficacy, and team-
work). Despite the number of reviews, the results are still inconclusive and often depend
on how “knowledge acquisition” and “skill competency” are operationalized. For instance,
a meta-analysis of 11 studies on VR endoscopy training for medical students found that
while VR improved procedure completion and overall performance ratings compared to
traditional methods, it resulted in fewer independent completions and showed no differ-
ence in other behavioral outcomes (Khan et al., 2018). Another VR systematic review of
nine studies revealed that only two showed improved knowledge acquisition in healthcare
professionals compared to the control groups (Abbas et al., 2023), suggesting that while VR
can enhance knowledge, it may not be consistently superior to other methods. However,
the same review found significant increases in skill competency in 19 out of 21 studies
comparing VR to control methodologies (Abbas et al., 2023), indicating a stronger impact
on practical skills. Other recent reviews of VR technology (Huai et al., 2024; Jallad & Işık,
2022; Uslu-Sahan et al., 2023) have shown the positive effects of I-XR on nursing students’
knowledge, skill performance, skill acquisition, and clinical reasoning. These varied results
suggest that the effectiveness of I-XR may depend on factors such as the specific technology
used, the type of training, and the outcome being measured. Further research is needed
to fully understand the conditions under which I-XR can optimize learning outcomes in
healthcare education.

The results are also mixed as to whether one type of immersive technology (AR, VR, or
MR) is more effective than another. For example, a systematic review of VR head-mounted
displays in medical education (Kovoor et al., 2021) showed significant increases in learn-
ing surgical procedures in seven of the 11 studies reviewed compared to other immersive
methodologies, but no differences were observed when directly compared with AR. How-
ever, when assessing anatomy knowledge, only one of the six studies reviewed showed
increased anatomy knowledge using VR. The authors concluded that VR technologies
outperformed conventional methods for learning surgical skills, but they were not superior
for learning anatomy knowledge. However, a recent meta-analysis (F. Q. Chen et al., 2020)
demonstrated that VR-based methodologies were significantly more effective than tradi-
tional methods, such as non-VR simulation or didactic instruction, in enhancing knowledge
acquisition among nursing students. Notably, this effect was specific to knowledge acqui-
sition and did not extend to performance time or skills. Despite mixed evidence for I-XR
technologies compared to non-immersive technologies in learning procedural skills and
knowledge acquisition, specific teaching and learning processes remain underexplored.
Therefore, how these methods use or adhere to learning theories to understand the delivery
of skills and knowledge could be another overlooked possibility for mixed evidence.

For example, educational learning theories offer valuable frameworks for understand-
ing how students acquire knowledge and develop skills. Researchers have identified 13
key theoretical perspectives relevant to medical education, including cognitivism, construc-
tivism, experiential learning, and reflective learning (Kaufman & Mann, 2010; Mann, 2011).
These theories guide a range of pedagogical approaches, from optimizing information
presentation (Issa et al., 2013) to fostering reflective practice (Van Merriënboer & Sweller,

foundation in learning theory, with many failing to support specific learning processes or
explicitly mention any theoretical framework.

However, despite the potential benefits of integrating learning theories into I-XR
research, several studies have identified concerning trends. Many studies on I-XR in
healthcare education either poorly described or completely omitted their pedagogical
approaches (Kivuti-Bitok et al., 2022). In one study designed to specifically assess whether
VR studies incorporated a conceptual framework or theory in their design, less than 3% of
papers on VR simulations did so (Jiang & Fryer, 2024). This lack of theoretical grounding
raises concerns regarding the rigor and generalizability of I-XR research in healthcare
education. Without a clear theoretical foundation, it is difficult to understand why certain
interventions are effective and how they can be optimized for different learning contexts.
This highlights the critical need for researchers to explicitly integrate learning theories into
the design, implementation, and evaluation of I-XR training programs.

1.3. Summary

In summary, I-XR is transforming healthcare education by providing immersive and
engaging learning experiences that enhance skill acquisition, knowledge retention, and
preparedness for clinical practice. This technology aligns with the evolving needs of
healthcare training, offering adaptable and flexible solutions for integrating cutting-edge
techniques. As technology continues to advance, I-XR is poised to play an increasingly
vital role in shaping the future of healthcare education.

While learning theories offer valuable insights into teaching and learning processes,
their application in healthcare education research remains surprisingly limited. This gap is
concerning because a strong theoretical foundation is essential for maximizing the pedagog-
ical impact of any educational intervention. The omission of learning theory is particularly
critical in the context of I-XR, where the novelty and complexity of the technology ne-
cessitate a strong pedagogical underpinning to guide its effective implementation. To
realize the full potential of I-XR in healthcare education, it is crucial to equip healthcare
educators with the necessary skills and resources to effectively integrate these technologies
into high-quality patient care training. This includes providing professional develop-
ment opportunities that focus on applying learning theories to the design and delivery of
I-XR-based learning experiences.

1.4. Purpose

This systematic review aimed to examine the effectiveness of I-XR training for health-
care students (e.g., medical and nursing students). We compared I-XR training methods
to traditional, non-immersive approaches to determine whether I-XR leads to greater im-
provements in skill competency and knowledge acquisition. These competencies were
assessed across multiple domains, including performance skills, objective performance
measures, clinical reasoning, internship grades, problem-solving skills, and skills knowl-
edge This review has significant implications for the healthcare field. First, it examines
six distinct outcomes related to skill competency and knowledge acquisition. Second, it
focuses on both graduate medical and nursing education across a wide range of techniques,



Behav. Sci. 2025, 15, 468 5 of 47

offering a holistic view of I-XR’s potential in healthcare training. Third, recognizing that
the effectiveness of I-XR may vary depending on the pedagogical approaches to which
they are compared, the review analyzes the results according to the type of non-immersive
(comparison) group used (e.g., didactic instruction, manikin-based training, simulated
patients). This nuanced approach provides valuable insights into the specific contexts in
which I-XR excels. Fourth, unlike many reviews that focus on a single technology, this
review encompasses the full breadth of I-XR techniques, including AR, VR, and MR allow-
ing for a comprehensive understanding of the diverse applications and benefits of I-XR in
healthcare education. Finally, and perhaps most importantly, it assesses each study for the
incorporation of learning theory, enabling an evaluation of whether skill competency and
knowledge acquisition are grounded in established pedagogical techniques. This critical
analysis highlights a significant gap in the current research and underscores the need for
a stronger theoretical foundation for I-XR implementation. To address this gap, in the
discussion section, we offer a preliminary framework for integrating embodied learning
theory into healthcare I-XR training, with implications for pedagogical practices. This
framework provides a valuable tool for educators and researchers seeking to maximize the
pedagogical effectiveness of I-XR in healthcare education.

theory. We also included a description of each study’s methods, results, and descriptive
statistics for comparisons of interest (Table 1). At least three researchers reviewed each
paper for the accuracy of the variables. Two coders coded the year, student sample, field,
learning theory, and type of I-XR method used. The agreement was >95% on the first pass.
The first and second authors coded the types of comparison groups and outcome measures
and made the final assessment for each. The initial agreement exceeded 85%. If the codes
were discrepant, the first author made the final decision.

## 🩺 概要（Abstract）
この論文は、医療・看護教育における **Immersive Extended Reality（I-XR）**—つまりVR（仮想現実）、AR（拡張現実）、MR（複合現実）—の教育効果を体系的に検証した **56件の研究レビュー**です。  
焦点は「**技能習得（skill competency）**」と「**知識獲得（knowledge acquisition）**」の2点。

- **結果の概要**
  - **VR研究の42.5%**, **AR研究の42.9%**, **MR研究（1件）**で、非XR手法よりも高い効果を確認。
  - **2.5%（VR）**と**7.14%（AR）**のみ、非XRが優位。
  - **26.8%**の研究では「一部の指標のみXRが優位」という混合結果。
- つまり、**XR教育は総じて有望**だが、効果が一定しない理由として**学習理論の欠如**が大きいと指摘しています。

---

## 🎓 背景と目的

### 1. 医療教育におけるシミュレーションの進化
従来の「見て、やって、教える（see one, do one, teach one）」モデルは安全性や熟練度の面で限界がある。  
そこでシミュレーション教育（SBME）が導入され、患者リスクを避けつつ技能を磨く手段となった【9†behavsci-15-00468.pdf†L30-L80】。

### 2. I-XRの登場
XR（Extended Reality）はVR/AR/MRを含む総称で、仮想と現実を融合した3D没入環境を提供。  
これにより、学生は実際の臨床に近い形で学習でき、**動機づけ・集中力・記憶定着**が向上する可能性がある【9†behavsci-15-00468.pdf†L150-L210】。

### 3. 研究上の課題
I-XR教育の有効性は報告されているが、結果はまちまち。  
主な理由は：
- 比較対象（講義、模擬患者、マネキンなど）が異なる
- 「知識」「技能」の定義が一貫していない
- **教育理論（learning theory）を明示していない研究が大多数（約97%）**【9†behavsci-15-00468.pdf†L390-L450】

## 🧩 理論的課題と提案

論文の最大の主張は「**教育理論が欠落している**」点。  
調査した56件のうち、**明確に理論を採用したものはほぼゼロ**。  
例としては、以下の理論が医療教育で有用にもかかわらず、XR研究ではほとんど応用されていない：
- 認知主義（Cognitivism）
- 構成主義（Constructivism）
- 体験学習理論（Experiential Learning）
- 省察的学習（Reflective Learning）

そこで著者らは、**「Embodied Learning（身体化学習）」に基づく新しい枠組み**を提案。  
XRの没入体験が「身体感覚・空間認識・情動反応」といった要素を活かせることから、  
**身体知（embodied cognition）と教育設計を統合することが鍵**だとしています。

---

## 🧠 教育実践への示唆
- I-XRは**医療教育の補助的ツール**として有望。  
- ただし、単なる「技術導入」ではなく、**学習理論と結びつけた設計（pedagogical design）**が不可欠。
- 教員側の研修や指導設計スキルも求められる。

---

## 📚 結論
- I-XRは医療・看護教育において**技能と知識の習得を大幅に支援し得る**。  
- しかし現状は「理論的根拠が乏しい技術導入段階」にあり、教育実践として成熟していない。  
- 今後は「**学習理論に裏打ちされたI-XR設計**」を目指すべきと結論づけています。

---

## 🧭 研究の意義
このレビューは、XR教育を「単なる技術トレンド」から「理論的に基づく教育実践」へ昇華させるための**基礎データと方向性**を提供しています。  
医療分野のみならず、他領域（工学・心理学・教育学）への応用にも示唆を与える内容です。

## 🧠 引用・主張にあたっての戦略と注意点

- **引用のバランス**：医療教育のレビュー論文（あなたが元にしたもの）と、上記の製造・整備分野のレビュー／実証例を併記する形がいい。例えば、「複数分野で XR による模擬体験が技能・知識習得を支える可能性が報告されており、医療教育においては …（Fugate他, 2025）、製造・整備分野においては …（Doolani 2020; Alam et al. 2025 など）」と書く。

      ```csharp
      using UnityEngine;

      public class EditorCameraController : MonoBehaviour {
          public float orbitSpeed = 3f;   // 右ドラッグ
          public float panSpeed   = 0.01f;// 中ドラッグ
          public float zoomSpeed  = 10f;  // ホイール
          public Transform pivot;         // 回転の中心
          private void Start() {
              if (pivot == null) {
                  var go = new GameObject("CameraPivot");
                  go.transform.position = Vector3.zero;
                  pivot = go.transform;
              }
              // カメラをpivotの子にして距離をとる
              transform.parent = pivot;
              transform.localPosition = new Vector3(0, 5, -10);
              transform.LookAt(pivot.position);
          }
          void Update() {
              // ズーム（ホイール）
              float scroll = Input.GetAxis("Mouse ScrollWheel");
              transform.localPosition += transform.forward * (scroll * zoomSpeed);

              // オービット（右ドラッグ）
              if (Input.GetMouseButton(1)) {
                  float dx = Input.GetAxis("Mouse X") * orbitSpeed;
                  float dy = -Input.GetAxis("Mouse Y") * orbitSpeed;
                  pivot.Rotate(Vector3.up, dx, Space.World);
                  pivot.Rotate(Vector3.right, dy, Space.Self);
              }
              // パン（中ドラッグ）
              if (Input.GetMouseButton(2)) {
                  float dx = -Input.GetAxis("Mouse X");
                  float dy = -Input.GetAxis("Mouse Y");
                  Vector3 right = pivot.right;
                  Vector3 up = Vector3.up; // 水平パン
                  pivot.position += (right * dx + up * dy) * (panSpeed * Vector3.Distance(transform.position, pivot.position) * 10f);
              }
          }
      }
      ```

      ```csharp
      public class PlacementController : MonoBehaviour {
          public PrefabRegistry registry;
          public Camera cam;
          public float gridSize = 0.1f;   // 10cm
          public LayerMask floorMask;     // Floorレイヤー

          string currentTypeId = null;

          Dictionary<string, GameObject> map;
          void Awake() {
              map = new Dictionary<string, GameObject>();
              foreach (var e in registry.entries) {
                  if (!map.ContainsKey(e.typeId) && e.prefab != null)
                      map.Add(e.typeId, e.prefab);
              }
          }

          public void EnterPlacement(string typeId) {
              currentTypeId = map.ContainsKey(typeId) ? typeId : null;
          }

          void Update() {
              if (string.IsNullOrEmpty(currentTypeId)) return;
              if (EventSystem.current != null && EventSystem.current.IsPointerOverGameObject()) return;

              if (Input.GetMouseButtonDown(0)) {
                  Ray ray = cam.ScreenPointToRay(Input.mousePosition);
                  if (Physics.Raycast(ray, out var hit, 1000f, floorMask)) {
                      Vector3 p = hit.point;
                      p.x = Mathf.Round(p.x / gridSize) * gridSize;
                      p.y = hit.point.y; // 床の高さ
                      p.z = Mathf.Round(p.z / gridSize) * gridSize;

                      var prefab = map[currentTypeId];
                      var go = Instantiate(prefab, p, Quaternion.identity);
                      go.AddComponent<PlacedObject>().Init(currentTypeId);
                  }
              }
          }
      }

      public class PlacedObject : MonoBehaviour {
          public string id;
          public string typeId;
          static int seq = 0;
          public void Init(string t) { typeId = t; id = "obj-" + (++seq).ToString("D4"); }
      }
      ```

## フェーズD：選択・ハイライト・削除・複製
### [フェーズのゴール]

1. **SelectionService を作る**

      ```csharp
      using UnityEngine;
      using UnityEngine.EventSystems;

      public class SelectionService : MonoBehaviour {
          public Camera cam;
          public LayerMask pickMask = ~0; // すべて
          public PlacedObject Current;
          public SelectionOutline outline; // ハイライト描画

          void Update() {
              if (EventSystem.current != null && EventSystem.current.IsPointerOverGameObject()) return;

              if (Input.GetMouseButtonDown(0)) {
                  Ray ray = cam.ScreenPointToRay(Input.mousePosition);
                  if (Physics.Raycast(ray, out var hit, 1000f, pickMask)) {
                      var po = hit.collider.GetComponentInParent<PlacedObject>();
                      if (po != null) Select(po); else Select(null);
                  }
              }
              if (Current != null) {
                  // 削除
                  if (Input.GetKeyDown(KeyCode.Delete)) {
                      Destroy(Current.gameObject);
                      Select(null);
                  }
                  // 複製
                  if ((Input.GetKey(KeyCode.LeftControl) || Input.GetKey(KeyCode.RightCommand)) && Input.GetKeyDown(KeyCode.D)) {
                      var dup = Instantiate(Current.gameObject, Current.transform.position + new Vector3(0.2f,0,0.2f), Current.transform.rotation);
                      var po = dup.GetComponent<PlacedObject>(); po.id = null; po.Init(po.typeId);
                      Select(po);
                  }
              }
          }
          public void Select(PlacedObject po) {
              Current = po;
              if (outline != null) outline.ShowFor(po ? po.gameObject : null);
          }
      }
      ```

2. **SelectionOutline（ハイライト）を作る（最小実装）**

   1) 「Project」→ **Create > C# Script** → `SelectionOutline`。  
   2) コードを貼る：  
      ```csharp
      using UnityEngine;
      using System.Collections.Generic;

      public class SelectionOutline : MonoBehaviour {
          public Material lineMat; // URP/Unlit Color 推奨
          List<LineRenderer> lines = new();
          GameObject target;

          void EnsureLines(int count){
              while(lines.Count < count){
                  var go = new GameObject("OutlineLine");
                  go.transform.SetParent(transform);
                  var lr = go.AddComponent<LineRenderer>();
                  lr.material = lineMat;
                  lr.widthMultiplier = 0.01f;
                  lr.positionCount = 2;
                  lr.useWorldSpace = true;
                  lines.Add(lr);
              }
              for(int i=0;i<lines.Count;i++) lines[i].gameObject.SetActive(i<count);
          }

          public void ShowFor(GameObject t){
              target = t;
              if(target==null){ EnsureLines(0); return; }
              var r = new Bounds(target.transform.position, Vector3.one*0.5f);
              var renderers = target.GetComponentsInChildren<Renderer>();
              foreach(var rr in renderers) r.Encapsulate(rr.bounds);

              // 8頂点
              Vector3[] v = new Vector3[8];
              Vector3 min=r.min, max=r.max;
              v[0]=new Vector3(min.x,min.y,min.z);
              v[1]=new Vector3(max.x,min.y,min.z);
              v[2]=new Vector3(max.x,min.y,max.z);
              v[3]=new Vector3(min.x,min.y,max.z);
              v[4]=new Vector3(min.x,max.y,min.z);
              v[5]=new Vector3(max.x,max.y,min.z);
              v[6]=new Vector3(max.x,max.y,max.z);
              v[7]=new Vector3(min.x,max.y,max.z);

              // 12辺（下4,上4,縦4）
              Vector3[,] edges = {
                {v[0],v[1]},{v[1],v[2]},{v[2],v[3]},{v[3],v[0]},
                {v[4],v[5]},{v[5],v[6]},{v[6],v[7]},{v[7],v[4]},
                {v[0],v[4]},{v[1],v[5]},{v[2],v[6]},{v[3],v[7]}
              };
              EnsureLines(12);
              for(int i=0;i<12;i++){
                  lines[i].SetPosition(0, edges[i,0]);
                  lines[i].SetPosition(1, edges[i,1]);
              }
          }
      }
      ```
   3) シーンに空の `GameObject` を作り `SelectionOutline` を付ける → `Systems` の `SelectionService.outline` に割り当て。  
   4) `lineMat` 用に **Material** を作成（URP/Unlit、色＝シアンなど見やすい色）。

   1) 「Project」→ **Create > C# Script** → `MoveTool`。  
   2) 以下を記述：  
      ```csharp
      using UnityEngine;
      using UnityEngine.EventSystems;

      public class MoveTool : MonoBehaviour {
          public Camera cam;
          public SelectionService sel;
          public float gridSize = 0.1f;
          public LayerMask floorMask;

          void Update() {
              if (EditModeService.I==null || EditModeService.I.Mode != EditMode.Move) return;
              if (sel.Current == null) return;
              if (EventSystem.current != null && EventSystem.current.IsPointerOverGameObject()) return;

              // マウス位置の床ヒット
              if (Input.GetMouseButton(0)) {
                  Ray ray = cam.ScreenPointToRay(Input.mousePosition);
                  if (Physics.Raycast(ray, out var hit, 1000f, floorMask)) {
                      Vector3 p = hit.point;
                      p.x = Mathf.Round(p.x / gridSize) * gridSize;
                      p.z = Mathf.Round(p.z / gridSize) * gridSize;
                      p.y = sel.Current.transform.position.y; // 高さは維持
                      sel.Current.transform.position = p;
                  }
              }
              // 矢印キーで微調整（±1グリッド）
              Vector3 nudge = Vector3.zero;
              if (Input.GetKeyDown(KeyCode.UpArrow)) nudge += new Vector3(0,0,gridSize);
              if (Input.GetKeyDown(KeyCode.DownArrow)) nudge += new Vector3(0,0,-gridSize);
              if (Input.GetKeyDown(KeyCode.LeftArrow)) nudge += new Vector3(-gridSize,0,0);
              if (Input.GetKeyDown(KeyCode.RightArrow)) nudge += new Vector3(gridSize,0,0);
              if (nudge != Vector3.zero) sel.Current.transform.position += nudge;
          }
      }
      ```

      ```csharp
      using UnityEngine;

      public class RotateTool : MonoBehaviour {
          public SelectionService sel;
          public int stepDeg = 15;

          void Update() {
              if (EditModeService.I==null || EditModeService.I.Mode != EditMode.Rotate) return;
              if (sel.Current == null) return;

              if (Input.GetKeyDown(KeyCode.Q))  Add(stepDeg);
              if (Input.GetKeyDown(KeyCode.E))  Add(-stepDeg); // Eで逆回転でも可（好みで）
          }
          void Add(int d) {
              var t = sel.Current.transform;
              var e = t.eulerAngles;
              e.y = Mathf.Round((e.y + d) / stepDeg) * stepDeg;
              t.eulerAngles = e;
          }
      }
      ```

### [フェーズのゴール]  
**配置／削除／移動／回転**の操作を**Ctrl/⌘+Zで取り消し**、**Ctrl/⌘+Y（またはShift+Z）でやり直し**できるようにする。

1. **コマンドの基底I/Fとスタックを用意**  
   1) 「Project」→ **Create > C# Script** → `CommandStack`。  
   2) 以下を記述：  
      ```csharp
      using System.Collections.Generic;

      public interface IEditorCommand {
          void Do();
          void Undo();
          string Label { get; }
      }

      public class CommandStack {
          Stack<IEditorCommand> undo = new();
          Stack<IEditorCommand> redo = new();
          public void Execute(IEditorCommand cmd) { cmd.Do(); undo.Push(cmd); redo.Clear(); }
          public void Undo() { if (undo.Count>0){ var c=undo.Pop(); c.Undo(); redo.Push(c);} }
          public void Redo() { if (redo.Count>0){ var c=redo.Pop(); c.Do(); undo.Push(c);} }
      }
      ```
   3) 「Project」→ **Create > C# Script** → `CommandService`。  
      ```csharp
      using UnityEngine;

      public class CommandService : MonoBehaviour {
          public static CommandService I;
          public CommandStack Stack = new();
          void Awake(){ I=this; }
          void Update(){
              bool ctrl = Input.GetKey(KeyCode.LeftControl) || Input.GetKey(KeyCode.RightCommand);
              if (ctrl && Input.GetKeyDown(KeyCode.Z)) Stack.Undo();
              if (ctrl && (Input.GetKeyDown(KeyCode.Y) || Input.GetKeyDown(KeyCode.Z) && Input.GetKey(KeyCode.LeftShift))) Stack.Redo();
          }
      }
      ```

      ```csharp
      public class PlaceObjectCommand : IEditorCommand {
          string typeId; Vector3 pos; Quaternion rot;
          GameObject instance;
          System.Func<string, GameObject> factory; // typeId→Instantiateする関数
          public string Label => "Place " + typeId;

          public PlaceObjectCommand(string typeId, Vector3 pos, Quaternion rot, System.Func<string,GameObject> factory){
              this.typeId=typeId; this.pos=pos; this.rot=rot; this.factory=factory;
          }
          public void Do()  { instance = factory(typeId); instance.transform.SetPositionAndRotation(pos, rot); }
          public void Undo(){ if (instance!=null) GameObject.Destroy(instance); }
      }

      public class DeleteObjectCommand : IEditorCommand {
          GameObject target;
          Vector3 pos; Quaternion rot; string typeId;
          System.Func<string, GameObject> factory;
          public string Label => "Delete " + (target? target.name : "obj");
          public DeleteObjectCommand(GameObject target, string typeId, System.Func<string,GameObject> factory){
              this.target=target; this.typeId=typeId; this.factory=factory;
              if (target!=null){ pos=target.transform.position; rot=target.transform.rotation; }
          }
          public void Do()  { if (target!=null) GameObject.Destroy(target); }
          public void Undo(){ var go = factory(typeId); go.transform.SetPositionAndRotation(pos, rot); }
      }
      ```

### Assistant (Turn 29)
原因はシンプルです。**プロジェクトの入力方式が「新Input System」なのに、スクリプトは旧API（`UnityEngine.Input`）を読もうとしている**ため、Unityが例外を投げています。

## 何が起きているか（エラーの意味）
- エラー文：
  > You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package in Player Settings.
- これは、**Player Settings の「Active Input Handling」**が  
  「**Input System Package (New)**」に設定されているのに、  
  スクリプト側で**旧API**（`Input.GetAxis(...)` など）を呼んでいる、というミスマッチが原因です。

---

## 解決パス（どちらかを選ぶ）

### パスA：とりあえず早く進める（推奨・即効）
**Active Input Handling を「Both」に切り替えて、旧APIも使えるようにする**方法です。  
MVP-1をサクッと進めたいならこれが最短です。後で新Input Systemに書き換えてもOK。

**手順**
1. 上部メニュー：**Edit > Project Settings...** を開く。  
2. 左ペイン：**Player** → 右側の **Other Settings** セクションへ。  
3. **Active Input Handling** を **Both** に変更。  
4. Unity から**再起動のダイアログ**が出たら **Restart**。  
5. 再生してカメラ操作が動くか確認。

> これで、あなたの `EditorCameraController`（`Input.GetAxis("Mouse X")` などの旧API）を**そのまま**使えます。

### パスB：ちゃんと新Input Systemに合わせる（将来の本命）
**旧APIをやめて、新Input SystemのAPIに差し替える**方法です。将来性は高いですが、少しだけ書き換えが必要です。

**要点**
- 旧：`UnityEngine.Input`  
- 新：`UnityEngine.InputSystem`（`Mouse.current` / `Keyboard.current` などを使う）

**差し替え例（`EditorCameraController`）**
```csharp
// 置換版（新Input System）
using UnityEngine;
using UnityEngine.InputSystem; // ← 追加

public class EditorCameraController : MonoBehaviour {
    public float orbitSpeed = 3f;    // 右ドラッグの回転速度
    public float panSpeed   = 0.01f; // 中ドラッグの平行移動速度
    public float zoomSpeed  = 10f;   // ホイールのズーム速度
    public Transform pivot;

    void Start() {
        if (pivot == null) {
            var go = new GameObject("CameraPivot");
            go.transform.position = Vector3.zero;
            pivot = go.transform;
        }
        transform.parent = pivot;
        transform.localPosition = new Vector3(0, 5, -10);
        transform.LookAt(pivot.position);
    }

    void Update() {
        if (Mouse.current == null) return; // デバイス未接続ガード

        // ズーム（ホイール）
        // 新Input Systemはスクロール量がベクタ。通常はY成分を使う。
        float scrollY = Mouse.current.scroll.ReadValue().y;
        if (Mathf.Abs(scrollY) > 0.0001f) {
            transform.localPosition += transform.forward * (scrollY * (zoomSpeed * 0.01f));
        }

        // オービット（右ボタン押しながらマウス移動）
        if (Mouse.current.rightButton.isPressed) {
            Vector2 d = Mouse.current.delta.ReadValue(); // マウス移動量
            float dx = d.x * (orbitSpeed * 0.02f);
            float dy = -d.y * (orbitSpeed * 0.02f);
            pivot.Rotate(Vector3.up, dx, Space.World);
            pivot.Rotate(Vector3.right, dy, Space.Self);
        }

        // パン（中ボタン）
        if (Mouse.current.middleButton.isPressed) {
            Vector2 d = Mouse.current.delta.ReadValue();
            float dx = -d.x;
            float dy = -d.y;
            Vector3 right = pivot.right;
            Vector3 up = Vector3.up;
            float dist = Vector3.Distance(transform.position, pivot.position);
            pivot.position += (right * dx + up * dy) * (panSpeed * dist * 0.1f);
        }
    }
}
```

**注意**
- スクリプト先頭に **`using UnityEngine.InputSystem;`** を必ず追加。  
- マウス移動量は `Mouse.current.delta.ReadValue()`、スクロールは `Mouse.current.scroll.ReadValue().y`。  
- 旧APIより感度が違うので、上の係数（`0.02f` や `0.01f`）は好みに調整してください。
