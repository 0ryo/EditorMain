# 卒業研究：SkillSync 総合ドキュメント

## 1. SkillSyncの全体概要 (機能、実装方法、研究概要)

本プロジェクト（SkillSync）は、学校や企業の技能教育において、設備コストや安全面、時間的制約といった課題を解決するために、非対面かつ安全・低コストに反復練習を行える「VR訓練環境（Meta Quest 3 / 2）」の構築を目指すプロジェクトである。

### 1-1. 研究の背景と目的
近年、作業の可視化や標準作業の理解促進を目的としたXR（Extended Reality）技術の導入が進んでおり、教育現場でもVR活用による安全性や効率性の向上が報告されている。しかし、実習内容に応じて新たに教材となるカリキュラムを作成するには、3Dアセットの準備や作業手順の定義など、教員に多大な負担が生じるという課題がある。
本研究の目的は、教員が専門的な3D開発知識を持たずとも、学習目標に即した実習教材を直感的に設計し、効率的に運用・配布できるワークフローを構築することである。

### 1-2. システム全体構成
本システムは、教材の開発コストを低減し、教員主導での教材設計を可能にするための統合的な枠組みであり、大きく以下の4要素から構成される。

1. **コース制作エディタ（カリキュラムおよび3Dワールド作成ツール）**：*※本研究における担当領域*
   指導者が実習環境を設計するためのPC向けスタンドアロンのUnityアプリケーション。
2. **VR実行アプリケーション**：
   Meta Quest 2/3 上で動作し、エディタから出力された設定データ（JSON）を読み込んで実習コースを再現し、必須手順の達成を確認するゲーティング機能によって学習進行を制御する。
3. **カリキュラム・3Dアセット**：
   学習目標・評価観点・手順記述、および配置用3Dオブジェクト群。初期題材として自動車の「タイヤ交換作業」を採用している。
4. **成績管理Webアプリケーション**：
   学習進捗・履歴・成績の可視化およびコースの配布を担い、システムの運用管理を一元化する。

### 1-3. 主な機能と実装アプローチ（エディタ部）
本研究で開発を担当する「**①コース制作エディタ**」は、指導者（教員）が「Blender風」の軽快な操作感で実習環境を作れるように設計されている。

- **3Dビューポート・配置操作**: 直感的なオブジェクトカタログ（Prefabカタログ）から、車両、工具箱、タイヤなどのオブジェクトを視覚的に配置、移動、回転、複製、削除する機能。
- **編集補助機能**: 正確に配置するための「グリッドスナップ機能」や、操作の取り消し・やり直しを行う「Undo/Redo機能」。
- **学習メタデータ編集**: レベルデザインの一環として、「車体固定」「タイヤ取り外し」といった、学習者に対する段階的な「必須手順（Required Actions）」や成功条件のメタデータをコース情報に紐づける機能。
- **検証機能とデータ出力**: 出力前に必須オブジェクトの有無などを簡易チェック（Validation）し、XRデバイスへ受け渡すデータとして、拡張性を重視した「JSON形式」で書き出す機能。

これにより、専門的なプログラミング知識を必要としない直感的なUIを提供し、VR実行環境側（描画最適化や物理挙動）とカリキュラム設計側（手順や配置）を疎結合に分離することで、教育現場での実用的な教材内製化基盤の実現を目指す。

## 2. 開発計画と実装機能 (各MVPにおける成果)

本システムは開発の確実な進行と段階的な検証・評価を行うため、機能を複数のMVP（Minimum Viable Product）フェーズに分割して実装している。現在、**MVP-3（インスペクタと使い勝手の向上）までの実装が完了**しており、以下に各フェーズで実装された中核機能とその実装アプローチについて概説する。

### 2-1. MVP-1：フレームワーク設計と基礎機能（オブジェクト配置機能の確立）

本フェーズでは、実習用オブジェクトを配置・操作するための根本となるエディタ基盤を構築した。

- **実装機能**
  - エディタ用カメラ操作（オービット、パン、ズーム）
  - オブジェクトカタログ機能と、ドラッグ＆ドロップ（またはクリック）による視覚的な配置機能
  - 配置済みオブジェクトの選択、移動、回転、複製、削除機能
  - 操作の取り消しとやり直し（Undo / Redo）
  - 整然とした配置を支援するグリッドスナップ（位置・回転）
- **実装方法・技術的アプローチ**
  - **アセット管理**: `ScriptableObject` を利用した「PrefabRegistry」を構築し、外部データ（JSON）とUnityの内部仕様（Prefab）を紐づけるID管理を採用した。
  - **操作の履歴管理**: `IEditorCommand`インターフェースを用いた「Commandパターン」を採用し、Stack構造を用いて状態の可逆性を担保することで強固なUndo/Redo制御を実現した。
  - **ハイライト描画**: 選択したオブジェクトを視覚的に強調するため、バウンディングボックスの八点から`LineRenderer`を用いて極めて低負荷なアウトライン描画を実装した。

### 2-2. MVP-2：データ入出力と妥当性検証（データ永続化）

本フェーズでは、MVP-1で配置した空間情報を外部に保存・共有するための拡張を行った。

- **実装機能**
  - 作成したシーンを独自のJSON形式としてエクスポートする出力機能
  - 外部のJSONファイルからシーンを復元するインポート機能
  - オブジェクトごとの一意識別子（ID）の自動発番
  - データ出力前の簡易Validation（必須オブジェクトの有無などの整合性チェック、開発中）
- **実装方法・技術的アプローチ**
  - **JSONシリアライズ**: 保守性と機能の拡張性に優れる「Newtonsoft.Json」ライブラリを導入し、`typeId`（カテゴリ識別）と絶対座標（位置・回転・スケール）をシリアライズ化している。
  - **オブジェクトライフサイクル管理**: 生成時に`PlacedObject`コンポーネント経由で自動的にUUID風の連番（obj-xxxx）を発行し、セッション中に一意性が損なわれないよう設計した（複製時には新しいIDを再発行する制御など）。

### 2-3. MVP-3：インスペクタと使い勝手の向上

本フェーズでは、シーン上の細かなオブジェクトのプロパティを直接編集できるUI拡張機能の実装を行った。

- **実装機能**
  - 選択中のオブジェクトの詳細値（座標、回転、スケール）を閲覧・直接入力で編集できる「インスペクタパネル」
  - 各オブジェクト固有の設定や、後で拡張可能にする任意のパラメータ群（`params`）の編集機能
  - 画面構成およびUIレイアウトの整理
- **実装方法・技術的アプローチ**
  - **動的UIの構築**: uGUIまたはUI Toolkitを用い、選択対象オブジェクトのデータ構造に基づいてインスペクタの項目が動的に生成されるデータバインディング的なアプローチを採用している。

### 2-4. MVP-4：学習手順メタデータの付与（シナリオの制御）

本フェーズでは「ただの3D空間」を「学習用コース」にするためのシナリオ・手順制御能力をエディタ側に持たせる実装を行った。

- **実装機能**
  - 「車体の固定」「正しいツールでの分解」など、学習上の到達目標となる必須手順（`RequiredActions`）を設定・編集するUI機能
  - アクションの追加・名称変更・順序入れ替え・削除機能
  - JSON スキーマのバージョニング対応（後方互換性の維持）
- **実装方法・技術的アプローチ**
  - エディタ側は具体的な物理挙動や正誤判定のロジックは実装せず、「手順のIDと名前、依存関係」だけを抽象的なメタデータリストとして編集・保存する設計としている。これにより本システムの処理負荷を抑えると同時に、Quest側（学習実行用アプリ）の自由度を侵害しない疎結合なアーキテクチャを実現している。
